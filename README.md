# VAuction

## Как пользоваться биржей

Откройте `/ah`: биржа сразу показывает каталог реальных товаров. `/market` и `/auction` — полные алиасы той же команды. Нажатие на товар открывает его карточку с отдельными действиями покупки и продажи.

### Быстро продать

Простой путь: `/ah` → товар → «Продать». Для покупки доступны 1/64/своё количество, для продажи — 1/«Всё»/своё количество с проверкой актуального инвентаря. Котировка и итог обновляются в том же окне; «Своя цена» открывает редактор ожидающей заявки. Точное количество и цена вводятся контекстной командой `/ah set`, которую предлагает сам GUI.

Лимитную заявку можно создать командой:

```text
/ah sell 32 64
```

Это значит: продать 64 точных предмета из инвентаря по 32 монеты за штуку. Такая заявка останется ждать, если подходящего покупателя пока нет.

### Быстро купить

```text
/ah
→ ЛКМ по товару
→ Купить сейчас
```

В сделке показываются количество, доступная ликвидность, итог и максимальная цена исполнения; использованные уровни остаются вторичной информацией в tooltip предмета. Если рынок изменился, покупка не пройдёт дороже подтверждённого максимума; недоступный остаток не превращается в ожидающую заявку.

Лимитная команда:

```text
/ah buy minecraft:copper_ingot 64 32
```

Она создаёт заявку на 64 предмета максимум по 32 за штуку и может ждать продавца. Точные NBT-варианты выбираются через GUI.

### Проверить заявки и забрать покупки

```text
/ah orders
/ah claims
```

Обе команды открывают один интерфейс «Моё»: сначала готовые покупки и возвраты, затем требующие внимания и активные/частично исполненные заявки. Готовый предмет забирается сразу кликом; активная заявка открывает компактное управление и подтверждение отмены. Завершённые и уже полученные записи этот feed не засоряют.

После каждой части команды нажимайте Tab: доступны подсказки предметов, количеств, рыночных цен, собственных заявок и получений. `/ah help` содержит кликабельные примеры.

## Настройка интерфейса

После первого запуска создаётся `config/vauction-ui.json`. Он настраивает только внешний вид и расположение интерфейса; типы действий и торговая логика из файла не меняются.

- `colors` — RGB-цвета без `#` или с ним;
- `texts` — все подписи, сообщения и динамические шаблоны;
- `lore` — порядок строк в карточках товаров и заявок;
- `buttons` — иконка (`minecraft:item_id` или ID предмета другого мода), прямые `name`/`lore` и их цвета;
- `layouts` — ячейки основных экранов. Нумерация ванильного сундука 9×6: `0..53`;
- `content` — массив ячеек, в которых выводятся товары или записи «Моего». Его длина одновременно задаёт размер страницы, максимум 45.

Настраиваются раскладки `catalogue`, `search`, `categories`, `product`, `immediate`, `limit`, `my` и `manage`. Экраны подтверждения отмены и предупреждения опасной цены имеют фиксированную безопасную раскладку.

Нельзя повторять занятые ячейки одного экрана, указывать слот вне `0..53`, неизвестный экран, поле или ID предмета. Ошибочный файл не применяется: продолжает работать последняя корректная версия. Новые поля после обновления мода автоматически дописываются без перезаписи ваших значений.

Применить изменения без перезапуска:

```text
/ah admin reloadui
```

Команда доступна операторам уровня 2. Старый вариант `/ah ui reload` сохранён для совместимости. При успешной перезагрузке открытые окна биржи закрываются, чтобы в них не оставались старые кнопки.

## Уведомления

Исполнения объединяются в одно сообщение за короткое окно, поэтому серия маленьких сделок не спамит чат и звуки. Онлайн-игрок видит купленное/проданное количество и остаток заявки. Если игрок был офлайн, при следующем входе показывается одна сводка только при наличии новых сделок или получений. Persistent cursor хранится в БД; повторный вход не повторяет уже показанную сводку.

## Безопасность торговли

- «Купить/Продать сейчас» использует marketable limit с ценой из подтверждённой котировки и семантикой partial IOC;
- котировка read-only: не резервирует деньги, не снимает предметы и не создаёт сделки;
- BUY исполняется только не дороже подтверждённого ceiling, SELL — только не дешевле floor;
- после bounded matching-прохода остаток закрывается существующим безопасным `cancel`;
- неиспользованный BUY-резерв освобождается штатной escrow-процедурой;
- непроданный SELL-остаток возвращается через существующие получения, без отдельной inventory-компенсации;
- durable IOC-маркер гарантирует закрытие остатка после crash/recovery;
- обычные лимитные заявки, matching, price/time priority, maker pricing и idempotency не изменены.

## Сервер и установка

VAuction — server-only мод для Minecraft Forge 1.20.1. GUI использует только ванильный `GENERIC_9x6`; custom Screen, MenuType, network channel и assets отсутствуют. VAuction и VEconomy клиенту не нужны.

- обязательная серверная зависимость: `economy_core` (VEconomy) 1.x;
- база: `<world>/vauction/auction.db` (SQLite);
- конфигурация: `<world>/serverconfig/vauction-server.toml`;
- конфигурация интерфейса: `config/vauction-ui.json`;
- V007 добавляет durable IOC-маркеры, компактный player notification cursor и targeted notification indexes;
- каталог и «Моё» ограничены 45 записями на страницу; unified feed сортируется и ограничивается непосредственно в SQL;
- notification flush и recovery имеют жёсткие лимиты работы.

Поместите `VEconomy-1.20.1-<version>-all.jar` и production JAR
`VAuction-1.20.1-<version>.jar` в серверную папку `mods/`.

## Сборка

```powershell
.\gradlew.bat clean build
```

Итоговый production-артефакт с SQLite JDBC находится в
`build/libs/VAuction-1.20.1-<version>.jar`. Он проходит ForgeGradle reobfuscation
и проверку байткода команд в составе обычного `build`.

Файл с суффиксом `-slim.jar` не содержит SQLite JDBC и не предназначен для
установки на сервер. Прямой запуск задачи `jarJar` также автоматически выполняет
`reobfJarJar`, поэтому получить из неё dev-артефакт с Mojmap-вызовами нельзя.
